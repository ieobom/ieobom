## 0. 한눈에

1. **위험한 것부터 해요.** 앱 안 통화(잠금 화면에서 받기 포함), 카카오 로그인, 통화 녹음을 먼저 실제 휴대폰 두 대로 확인해요. 여기가 막히면 다른 화면을 만들어도 소용없어요.
2. **디자인과 상관없는 것부터 해요.** 표, 보는 사람 규칙, DB 함수, 서버 함수, 통화, 알림을 먼저 끝내요. 39차가 10/9에 고정돼서 화면은 서버 함수가 준비되는 대로 붙여요.
3. **시범 운영 첫날부터 모든 기능을 켜요.** 질문·근황·통화 메모 초안·여쭤볼 이야기가 첫날부터 돌아가야 해요. 그래서 첫 빌드(관문 3) 뒤 일주일 안에 나머지 기능을 EAS Update로 채워요.
4. **작업은 커밋 109개로 쪼갰어요.** 하나에 반나절~하루, 합치면 약 78 사람·일이에요. 1주차에 3개만 끝나서 일정을 1주 밀었어요(3장). 늦어지면 '(되면)' 표시부터 빼요.
5. **무거운 경로를 처음부터 가볍게 만들어요.** 통화는 받은 뒤에만 통화방에 들어가고, 통화 녹음은 두 사람이 모두 켰을 때만 하고 글로 바꾸자마자 지워요. 사진은 휴대폰에서 줄여 올리고, AI는 필요할 때 한 번만 불러요(5장).

## 2. 디자인이 바뀌어도 덜 흔들리게

39차로 고정됐지만, 시안 담당이 7장 목록을 반영하면서 문구와 몇몇 화면이 또 바뀌어요. 그래서 디자인이 바뀌어도 고칠 곳이 적게 만들어요.

- **상태는 서버가 정하고, 화면은 그리기만 해요.** 홈 카드가 무엇이고 어떤 순서인지(못 받은 전화 → 지금 편한 시간 → 답할 질문 → 새 근황 → 통화 메모 초안 → 질문 기다림)는 DB 함수가 이름 붙인 상태값으로 돌려줘요. 시안이 바뀌면 그리는 부분만 고치면 돼요.
- **디자인 값과 공통 부품을 한 곳에 둬요.** 색·간격·글자 크기·큰 글씨 배율, 버튼·카드·기록 줄·아래 창. 39차의 "같은 정보는 같은 모양" 원칙과도 맞아요.
- **문구를 한 파일에 모아요(`src/copy/ko.ts`).** 시안 담당이 문구를 고치면 이 파일만 고치면 돼요.
- **기능 켜고 끄기 표(`app_config`)를 둬요.** 사용량이 튀거나 업체가 멈추면 앱을 다시 내지 않고 AI·통화 녹음을 끌 수 있어요.
- **화면 번호(#NN) 대신 기능 이름을 써요.** 화면 번호는 차수마다 바뀌어요.

| 단위 | 디자인 영향 | 언제 |
|---|---|---|
| 1 개발 기반 · 2 데이터 · 11 운영 | 없음 | 1~2주차부터 |
| 5 통화 · 6 알림 · 7 통화 녹음·말→글·AI의 서버 쪽 | 낮음 (OS 기본 전화 화면 + 우리 화면 조금) | 2주차부터 |
| 3 로그인 · 4 가족 연결 · 7 메모 화면 · 8 질문 · 9 근황 | 중간 (흐름은 39차대로, 문구는 바뀔 수 있음) | 3주차부터 |
| 10 홈·기록·마이 | 높음 | 서버 함수는 4주차, 화면은 5주차 |

## 4. 작업 단위와 커밋

### 커밋 규칙

- **한 커밋 = 확인할 수 있는 변화 하나.** 반나절~하루 크기예요. 이틀이 넘으면 쪼개요.
- **제목은 `영역: 한 일`로 써요.** 아래 번호를 본문 첫 줄에 적어요(예: `계획 5-3`).
  - 서버: `db`(표·규칙·DB 함수), `fn`(서버 함수), `cron`(정해진 시간 작업)
  - 앱: `app`
  - 공통: `chore`, `ci`, `docs`, `release`, `ops`
- **한 커밋은 한 영역만 바꿔요.** 서버 일과 앱 일이 같이 필요하면 커밋을 둘로 나누고, 서버 커밋을 먼저 해요.
- **표를 만드는 커밋에는 보는 사람 규칙(RLS)과 그 검사(pgTAP)를 같이 넣어요.** 규칙 없이 표만 올리지 않아요.
- **서버 함수 커밋에는 시험(Deno test)을 같이 넣어요.** 바깥 서비스는 가짜로 대신해요.
- **폴더나 주요 파일을 더하면** 구조도를 갱신해요(`pnpm structure`). CI가 확인해요.
- **가지(branch)는 단위별로 짧게 따요.** 2~5커밋마다 PR → CI 통과 → main. 지금 GitHub 등급에서는 비공개 저장소에 main 보호 규칙을 걸 수 없어서, 팀 약속으로 지켜요.

**커밋 점검 기준** (계획서를 검토할 때 쓴 기준)
- 확인 방법이 적혀 있다.
- 하루 안에 끝난다.
- 영역이 하나다.
- 먼저 필요한 커밋이 앞에 있다.
- 디자인에 기대는 커밋은 그 화면의 서버 함수 뒤에 있다.

## 7. 시안·정책 문서에 반영해 달라고 전할 것

새 39차(10/9)를 기준으로, 시안 담당에게 아래를 전해요(12-1). 앞의 셋은 개발 방식이 바뀌어서 꼭 고쳐야 해요.

**반영 결과 (10/10 39차 3회):** 1~6번과 9~13번이 들어갔어요. 처리방침의 Gemini·LiveKit 보관 기간은 '확인한 뒤 적습니다'로 비워 뒀어요. AI 모델을 정하면(1장) 2번을 다시 맞춰요. 7번 Apple 로그인은 기능명세서에 없어서 시안에서 뺐어요. 개발은 앱 심사 대비로 3-8을 남겨 둬요. 8번 60초 남은 시간 표시도 시안에 넣지 않았어요. 개발은 60초에서 자동으로 멈추게 해요(7-4). 통화 뒤 메모는 글로만 쓰게 바뀌었어요(7-12).

1. **통화 메모 초안은 녹음으로 만들어요 (10/10 결정).** 39차의 '녹음 파일은 만들지 않음', '녹음하지 않아요' 문장을 고쳐요. AI 사용 안내 4번, 처리방침, 약관, 도움말 '통화 내용이 저장되나요?', 선택 동의 문구에 있어요.
   - 고칠 내용: 두 사람이 모두 켰을 때만 통화를 녹음해요. 글로 바꾸면 녹음은 바로 지워요(늦어도 1시간 안). 글로 바꾼 통화 내용은 초안을 만든 뒤 바로 지워요.
   - 통화 중 안내 줄과 전화 걸기 확인 문구도 '녹음해서 글로 바꿔요'가 드러나게 고쳐요.
2. **AI 업체**: OpenAI(GPT-4o mini) → Google(Gemini 3.5 Flash-Lite). 처리방침 국외 이전, AI 사용 안내, '최대 30일 보관' 문장(Gemini 유료 등급 기준으로 다시 확인)을 고쳐요. 통화 글도 AI로 가니 그 항목을 더해요.
3. **통화 업체**: LiveKit(미국)이 통화와 통화 녹음을 처리해요. 처리방침의 위탁·국외 이전 빈칸(18 검수 4-1)을 채워요. 녹음 파일은 우리 서버(서울)에 잠깐 올렸다 지워요. 말→글 업체 표기는 '네이버클라우드 CLOVA'로 하고, 리턴제로는 7-3 비교 뒤 쓰기로 하면 남겨요.
4. **초안 만드는 시간**: '몇 초'가 아니라 통화 길이에 따라 더 걸릴 수 있어요. 만드는 중 화면에서 나가도 되고, 다 되면 홈의 통화 메모 초안 카드로 와요. 실제 시간은 관문 2(10/23)에 알려 드려요.
5. **1분 미만 통화는 초안을 만들지 않아요**: '초안 없을 때 · 못 만듦' 문구가 이 경우도 맞는지 봐요.
6. **사진 AI 태그 뺌**: 사진 고르기의 태그와 '고른 사진은 AI가 봐요' 문구, 처리방침·AI 안내의 사진 항목을 지워요. 사진만 보낸 근황은 주제를 직접 골라요.
7. **아이폰 'Apple로 로그인' 버튼**: 가입·로그인 화면에 더해요('카카오로 계속하기' 아래).
8. **말로 답하기 60초 상한**: 녹음 중 남은 시간을 보여 줘요.
9. **질문 오는 요일**: 주 1번 목, 주 2번 월·목, 주 3번 월·수·금이에요. 시안의 '다음 질문' 날짜를 맞춰요.
10. **전화는 가장 최근에 쓴 휴대폰 하나로 울려요**: 도움말 '휴대폰을 바꿨어요'에 넣어요.
11. **아이폰 기본 통화 화면 이름**: '이어봄 · 엄마'로 해요(18 검수 1-8). 지금은 알림에만 있어요.
12. **상대가 탈퇴해서 끊긴 경우의 문구**: 지금은 끊김 문구 하나라 '다시 이어지면'이 탈퇴한 경우와 맞지 않아요(18 검수 2-2).
13. **마이크 권한 설명**: 짧은 녹음과 통화 녹음(두 사람이 켰을 때)을 함께 적어요(12-3).
14. **부모님이 자녀를 초대할 때 엄마 · 아빠 고르기** (10/13 개발 중 발견): '누구와 이어볼까요'에서 자녀를 고르면 내가 엄마인지 아빠인지 정하는 곳이 없어요. 받는 자녀 화면은 '엄마의 자녀로 이어져요'라서 필요해요. 자녀를 고른 뒤 '나는 엄마 / 아빠' 한 번 고르기를 더해 주세요.

| 통화방 · 입장 열쇠 | 두 사람이 목소리를 주고받는 방과, 그 방에 들어가는 일회용 열쇠 |
| 통화 녹음 (Egress) | LiveKit이 통화방의 소리를 파일로 만들어 우리 저장소에 올리는 기능 |
| 단문 인식 · 장문 인식 | 단문은 60초까지 짧은 녹음을 바로 글로 바꾸는 것, 장문은 긴 녹음 파일을 맡기고 끝나면 결과를 받는 것 |
| VoIP 알림 · CallKit | 꺼진 아이폰을 전화처럼 울리는 알림과, 그때 뜨는 아이폰 기본 전화 화면 |
| 참가자·분 | 통화방에 한 사람이 1분 있으면 1. 두 사람이 15분 통화하면 30 |
| 기능 켜고 끄기 표 | 앱을 다시 내지 않고 기능을 켜고 끄는 표(`app_config`) |
| pgTAP | 보는 사람 규칙과 DB 함수가 맞게 동작하는지 자동으로 검사하는 도구 |
